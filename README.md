# 角色一致性工具箱（Character Consistency Kit）

> 一个最小实验仓库：验证「角色卡写具体行为而非形容词」能否降低角色扮演中的 OOC（Out-of-Character，出戏）率。

## 这是什么

很多角色扮演项目跑完几十轮对话，只能凭感觉说"还行"。这个仓库试图把"像不像"变成可记录、可复现的证据：

- 一份结构化的原创角色卡
- 一套 20 轮的情境测试提纲（覆盖日常、专业、情感、超纲、连续追问）
- 一组「改前 vs 改后」的 OOC 翻车记录
- 一个可复现的基准线脚本

**不包含**任何受版权保护的角色数据。示例角色"巫屿"为原创。

## 核心发现：形容词约束会失效，行为约束才管用

同一个角色，同一组问题，只改 system prompt 的写法：

| 场景 | 改前（形容词描述） | 改后（行为+台词模板） |
|---|---|---|
| 被问"用一句话总结你自己" | "我是个长生不老、对人客套话不感冒的旧书店老板。" ❌ 暴露核心秘密 | "书多，话少。" ✅ 短、含蓄、未暴露身份 |
| 被求助"帮我找个人" | "找人？这可不容易。你要找谁？" ❌ 直接接下求助，未先质疑 | "找人？为什么找我？你确定这事靠谱吗？" ✅ 按设定先质疑动机 |
| 被问"你懂历史吗" | "历史书多得很，自己挑。" ❌ 反向 OOC，该话多时话少 | "懂点，你想知道哪个朝代的？" ✅ 主动追问 |

详细记录见 [`ooc_log.md`](ooc_log.md)。

## 怎么复现

依赖：本地安装 [Ollama](https://ollama.com/)，并拉取模型 `qwen2.5:7b`。

```bash
pip install requests
ollama run qwen2.5:7b   # 先确认模型能跑，然后 /bye 退出
python run_dialog.py    # 自动跑完 20 轮，输出 baseline_dialog.json
```

脚本会把 system prompt 放在 `system` 角色里，而不是当普通消息发——这个区别决定了模型是"成为角色"还是"表演角色"。

## 角色卡设计要点

角色卡基于 Character Card V2 的字段，额外加了三个扩展字段：

- `timeline_constraints`：时间线约束（能聊什么时期的事）
- `taboo_topics`：禁忌话题 **+ 被问到时的回避策略**（只写"不能聊"不够，必须写"怎么挡回去"）
- `decision_tendencies`：决策倾向（遇到某类情境时先做什么、再做什么）

最重要的经验：**每一个"秘密"，都必须配一套"被问到时的应对剧本"，否则模型一定会漏。**
